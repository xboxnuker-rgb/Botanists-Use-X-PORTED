| Schedule I branch | Backend | Status |
| --- | --- | --- |
| Main/default 0.4.7f12 | IL2CPP | Version 2.0.0 passed soil-pourer, small/large sprinkler, combined-build, and multiplayer host/client testing. |
| Alternate | Mono | Not supported by this compatibility release. |

IL2CPP and Mono builds are not interchangeable. The legacy mods patched the removed `PotActionBehaviour` type and fail during Harmony initialization on the current game API.

## Installation

1. Close Schedule I completely.
2. Open the game's installation directory and then its `Mods` folder.
3. Remove the legacy Fortis DLLs and any older Botanists Use X DLLs.
4. Extract your chosen DLL from its named release ZIP into `Schedule I/Mods`.
5. Launch the game and confirm the blue GSVS startup banner appears in the MelonLoader console.

![Windows Explorer open at the Schedule I Mods folder](docs/images/mods-folder-location.png)

Install either the combined DLL by itself or either/both individual DLLs. **Never install `BotanistsUseX.dll` alongside an individual Botanist Use DLL** because that would apply the same Harmony patches twice.

In multiplayer, every participant should use the same DLL layout and version. The host owns soil-pourer capacity and charge state for the session.

## At a glance

- **Prepare the next crop:** idle botanists top up eligible soil pourers after their normal planting work.
- **Carry more soil:** each pourer stores 1–8 configurable bags and defaults to 2.
- **Dispense one charge:** a 2/2 pourer empties in two visible stages instead of one use clearing it.
- **Plant immediately:** a botanist using stored soil arrives with the configured seed and plants it in the same action.
- **Use both sprinkler sizes:** ready small and large sprinklers replace the hand-watering result.
- **Move on promptly:** the botanist walks away once a sprinkler starts instead of remaining in the watering animation.
- **Keep vanilla fallbacks:** normal soil and hand-watering jobs remain available when no eligible linked device exists.
- **Stay synchronized:** custom soil-pourer capacity, charges, prompts, refills, dispensing, and join-in-progress state are host-authoritative in multiplayer.

## Features and configuration

### Soil Pourer

- Finds pourers from each device's authoritative linked-pot list.
- Supports manual and botanist top-ups with matching soil.
- Shows charge-aware interaction text and proportional fill height.
- Persists per-pourer charges under the selected mod's `UserData` directory.
- Routes refill-only work to the pourer while preserving the first planting walk to the pot.

### Sprinkler

- Supports both small and large linked sprinklers.
- Activates a ready device instead of applying the botanist's hand-watering result.
- Prevents duplicate watering jobs while that sprinkler is already active.
- Releases the worker immediately after activation.

### Combined configuration

`UserData/BotanistsUseX/configuration.json`:

```json
{
  "soilPourerEnabled": true,
  "autoRefillSoilPourers": true,
  "soilPourerCapacity": 2,
  "allowManualMultiBagFill": true,
  "sprinklerEnabled": true,
  "debug": false
}
```

The individual builds use compatible directories:

- `UserData/BotanistUseSoilPourer/configuration.json`
- `UserData/BotanistUseSprinkler/configuration.json`

Capacity is clamped to 1–8. Valid configuration files are rewritten at startup so new settings appear without requiring users to delete their existing file.

## Multiplayer

Gameplay changes are server-authoritative. The host broadcasts soil-pourer capacity, charge changes, staged dispense visuals, fill prompts, refills, and current state for joining clients through the game's existing FishNet RPC paths. Remote fill and handle interactions are validated and performed by the host.

The host capacity temporarily replaces a client's local capacity while connected. That client's own setting remains available for their own game.

## Troubleshooting

### The mod does not appear

- Confirm your chosen DLL is directly inside `Schedule I/Mods`.
- Confirm MelonLoader 0.7.0 Open-Beta is loading.
- Remove the legacy Fortis DLL and any duplicate combined/individual layout.

### The console reports an undefined Harmony target

The DLL was built for another Schedule I version. Use the release that explicitly names your installed game version.

### Multiplayer shows one bag or mismatched pourer state

- Install the same `2.0.0` DLL layout on the host and every client.
- Remove older copies from every player's `Mods` folder.
- Let the host's configured capacity control the session.

### A botanist uses normal soil or hand watering

- Confirm the intended device is linked to that pot.
- Confirm the pourer contains compatible soil or the sprinkler is ready and has water.
- Confirm the matching feature is enabled in the combined configuration.

For reproducible reports, include the game version, mod version, host/client role, installed Botanist DLL names, reproduction steps, and `MelonLoader/Latest.log` on the [GitHub issue tracker](https://github.com/GSVS-UK-ACM/Botanists-Use-X-PORTED/issues).

## Building the IL2CPP version

Use references generated by the exact game version being targeted; never commit those game files.

```powershell
.\scripts\build-il2cpp.ps1 `
  -MelonLoaderRoot 'C:\Games\Schedule I\MelonLoader'
```

Create all three distributable archives with:

```powershell
.\scripts\package.ps1 `
  -MelonLoaderRoot 'C:\Games\Schedule I\MelonLoader'
```

Outputs go to ignored `bin/Il2Cpp` and `artifacts` directories. Exact verification results and hashes are recorded in [docs/HANDOVER.md](docs/HANDOVER.md).
